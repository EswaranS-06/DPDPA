# ADR-0009: Assurance, registers, visuals, outputs and management (C22 to C27)

Date: 13 Oct 2026. Status: accepted by the build; ComplyX's legal review of the breach notice wording, the DPIA prompts and every document pack template is pending. Decision 14, and decision 13 for the document pack, are replaced by ADR-0010: the document pack is built on ComplyX's own template library.

ComplyX compared DUATF with three other compliance tools and asked for the additions it lacked: a quality check before sign-off, expiry alerts, registers for processors, breaches and rights requests, a DPIA record, maturity targets, a Word report with charts, a board memo, a roadmap, an assessment statement, a standards crosswalk, a document pack, five visuals, sign-off, email reminders, a remediation board and calendar, a supported import command and a public page for rights requests. The ideas are built in DUATF's own code and model. They are planned as six phases (C22 to C27) in `docs/DUATF-Coding-Plan.md` and `plan/plan.yaml`.

| # | Decision | Why | Consequence |
|---|---|---|---|
| 1 | **Nothing here changes the knowledge base.** Penalty items, phase dates and standard references are read from the published release; new wording (quality rules, notice contents, templates) lives in the code | ComplyX has a draft release open on the live instance that only it may publish | The live draft is untouched; a later phase can move the templates into the knowledge base editor |
| 2 | **The quality check is computed each time, never stored.** Rules read the cycle's answers, evidence, findings, actions and risks and return issues: an error (the answer cannot stand as recorded), a warning (should be dealt with) or a note. A Yes with no accepted evidence is an error where the question asks for evidence and a warning otherwise | A stored list would go stale with the next answer; severity must not cry wolf on questions that need no document | One pure rule set (`quality.ts`), tested rule by rule (TC-C22.1-01) |
| 3 | **Evidence is "expiring" 30 days before its valid-until date and "expired" after it.** An answer whose evidence has all expired is an error in the quality check | A certificate or contract that has run out no longer supports the answer | Shown on the evidence pages and in "Needs your attention" |
| 4 | **A risk is accepted until a date.** New acceptances need the date; when it passes the acceptance has lapsed: it is renewed with a new date and reason, or the risk is reopened. Nothing reopens by itself | An acceptance is a decision for a period, not for ever; DUATF must not change a client's decision silently | `risk.accepted_until`; earlier acceptances have no date and are flagged as a note |
| 5 | **Sign-off is a decision by a named person.** Whoever may check answers sends the cycle to an approver (a Senior auditor or an Administrator) with a deadline. The cycle is then "in review" and its answers are locked. Only that approver approves (the cycle completes) or asks for changes (it reopens). A Senior auditor may still complete a cycle directly, which is recorded as their own sign-off | The self-audit edition must still work for one senior auditor; a junior auditor's cycle gets a second pair of eyes | Capability `assessment.signoff`; table `assessment_signoff` with the issue counts and posture at the decision. An Auditor can no longer complete a cycle alone |
| 6 | **The processor register is matched to the RoPA by name.** A register entry has other spellings; an activity's processors stay the text the RoPA holds. "Build from the RoPA" adds an entry for every processor not yet registered | The RoPA round-trips through Excel as text; a second model of the same answer would disagree with it | No change to `processing_activity`; the register shows the activities and personal data of every matching name |
| 7 | **Every personal data breach is intimated; severity is triage only.** The register runs the clocks from the time the organisation became aware: the detailed report to the Board within 72 hours (R7(2)(b)) unless a longer period allowed by the Board is recorded, and the CERT-In report within 6 hours when the breach is a cyber incident. The first intimation to the Board and the intimation to each affected Data Principal are "without delay" and have no fixed clock | s.8(6) has no risk threshold, unlike other regimes; the knowledge base cites these periods (OBL-BRE-01 to 03, LNK-CERT-01) | A breach cannot be closed without its intimations or a recorded reason |
| 8 | **The rights register holds a reference to the requester, not their identity.** The form asks for the client's ticket or customer reference and says not to enter a name unless it is needed | DUATF is the auditor's tool; it should not become a second store of the client's Data Principals | The public request page (C27.4) is the one place a requester's contact is taken, and only what they type |
| 9 | **A DPIA follows s.10(2)(c)(i):** the rights of the Data Principals affected, the purpose, the assessment of the risk to those rights and its management, with necessity and proportionality added as good practice. One DPIA per activity, reviewed on a date | The Act defines the DPIA's contents for a Significant Data Fiduciary; others use the same shape voluntarily | `dpia` and `dpia_risk`; risks are rated likelihood x impact in the firm's bands |
| 10 | **Maturity levels:** a domain's level is the mean of its maturity answers (0 to 4). A domain with only Yes, Partial and No questions uses 3, 2 and 0, the lowest level each outcome stands for. Targets default to 3 (Defined), the level that counts as compliant | The question bank already maps levels 3-4, 2 and 0-1 to those outcomes | Gaps are ranked by gap x penalty weight (the Schedule maximum over Rs 50 crore) |
| 11 | **Charts are drawn by DUATF's own geometry, without a chart library.** Pure functions return shapes; the pages render them as SVG and the Word report as pictures | Five small charts do not justify a dependency; the same picture must appear on the page and in the report | `charts.ts`, tested by coordinates (TC-C24.2) |
| 12 | **Penalty exposure never adds the maximums up.** It lists each Schedule item that has an open gap, with the item's maximum and the gaps under it | The Board decides the amount having regard to the matters in s.33(2); a summed "exposure" would read as a prediction | The same wording in the page, the memo and the report |
| 13 | **Word files are written with the `docx` library; PDF is by printing or from Word.** The gap-assessment report, the board memo, the assessment statement and the document pack are .docx; the roadmap is an Excel sheet and a printable page | Consultants edit their deliverables; a second PDF engine would double the layouts to maintain | `feature-compliance-api/src/documents/` |
| 14 | **Document templates carry a legal review status tied to their wording.** A template is "awaiting legal review" until an Administrator marks it reviewed; the mark is stored against a hash of the wording, so a later change asks for review again. Unreviewed documents say so on their first page | The wording was drafted by the build, not by counsel | `document_template_review` |
| 15 | **Reminders are one message a day per person**, sent over SMTP when a server is set in the environment (`SMTP_HOST` and the rest), and logged so a second run sends nothing. `pnpm duatf remind` sends them; the setup can schedule it | No mail leaves the instance until ComplyX configures a server | `reminder_log`; tested with a transport that records messages |
| 16 | **Import is a command over the services**, reading one JSON spec (client, departments and their questions, answers, evidence files, checks), validated before anything is saved, with a dry run. It only fills what is missing | The first client import was a one-off script; the next one should be repeatable and reviewed | `tools/assessment-import`, `pnpm duatf import` |
| 17 | **The public request page is off until switched on per client**, sits behind an unguessable link, takes only the request kind, a contact and the details, limits repeated posts and writes straight into the rights register as "received" | A public form on the audit tool must not expose anything or be a spam target | `client_public_link`; nothing about the client beyond its name is shown |
